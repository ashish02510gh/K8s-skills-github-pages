Supply Chain Overview

Supply chain security covers the entire journey from source code to production. Vulnerabilities can be introduced at any stage: during development, build, scanning, signing, registry, or deployment. A comprehensive approach protects against all attack vectors.

🔴 Critical: Supply chain attacks are increasing. Recent major breaches involved compromised dependencies and tools.

Secure Development

Source Code Security

  • Use version control (Git) with enforced access control
  • Require code reviews before merge
  • Implement branch protection rules
  • Sign commits with GPG keys
  • Scan code for secrets

Dependency Management

# Scan dependencies for vulnerabilities
npm audit
pip-audit
go list -json -m all | nancy sleuth
cargo audit

SBOM (Software Bill of Materials)

Track all components and dependencies:

# Generate SBOM with Syft
syft packages -o json docker:myimage:latest > sbom.json

# Generate with CycloneDX format
syft packages -o cyclonedx docker:myimage:latest > sbom.xml

Secure Build Process

CI/CD Pipeline Security

  • Run tests automatically on all PRs
  • Enforce security scanning in pipeline
  • Require approval before production deployment
  • Use signed commits and tags
  • Implement audit logging

Build Isolation

  • Use separate build environments
  • Clean build environment between builds
  • Restrict network access during build
  • Run builds as non-root

Build Configuration

# Use minimal base images
FROM alpine:latest as build
# Build application
FROM distroless/base:nonroot
COPY --from=build /app /app
USER nonroot

Artifact Verification

Sigstore - Keyless Signing

Sign artifacts using OpenID Connect:

# Sign container image
cosign sign registry.example.com/myapp:v1.0

# Verify signature
cosign verify registry.example.com/myapp:v1.0

# Sign with custom key
cosign sign --key cosign.key registry.example.com/myapp:v1.0

Provenance Attestation

# Create provenance statement
cosign attest --predicate provenance.json registry.example.com/myapp:v1.0

# Verify provenance
cosign verify-attestation registry.example.com/myapp:v1.0

SLSA Framework

  • Supply-chain Levels for Software Artifacts
  • Defines security levels 0-3
  • Provides framework for secure builds
  • Requires provenance and attestation

Secure Deployment

Binary Authorization

Only deploy signed images:

apiVersion: binaryauthorization.grafeas.io/v1beta1
kind: Policy
metadata:
  name: require-signed
spec:
  admissionWhitelistPatterns:
  - namePattern: gcr.io/myproject/*
  defaultAdmissionRule:
    requireAttestationsBy:
    - projects/myproject/attestors/prod-attestor
    evaluationMode: REQUIRE_ATTESTATION

Policy-as-Code

  • Define deployment policies as code
  • Use Open Policy Agent (OPA/Gatekeeper)
  • Enforce policies through admission controllers
  • Version control policies
