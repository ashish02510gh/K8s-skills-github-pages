Network Policies Overview

Network Policies define rules for network traffic between pods. By default, Kubernetes allows all pod-to-pod communication. Network Policies implement a zero-trust model where you explicitly allow required traffic.

💡 Key Concept: Think of Network Policies as firewall rules for pods. They control ingress (incoming) and egress (outgoing) traffic based on labels and selectors.

Network Policy Basics

Pod Selection

  • Use label selectors to target pods
  • Target specific namespaces
  • Combine multiple selectors with AND logic

Traffic Direction

  • Ingress: Incoming traffic to pods
  • Egress: Outgoing traffic from pods
  • Both can be controlled independently

Traffic Types

  • Pod-to-pod within namespace
  • Pod-to-pod across namespaces
  • Ingress controller to pod
  • Pod to external services

Network Policy Examples

1. Deny All Traffic

Start with default deny, then allow required traffic (zero-trust approach):

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all
  namespace: production
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress

2. Allow Frontend to Backend

Allow specific traffic between application tiers:

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-backend
  namespace: production
spec:
  podSelector:
    matchLabels:
      tier: backend
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          tier: frontend
    ports:
    - protocol: TCP
      port: 8080

3. Allow from External Ingress

Allow traffic from ingress controller:

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-from-ingress
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: web
  policyTypes:
  - Ingress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: ingress-nginx
    ports:
    - protocol: TCP
      port: 80

Best Practices

  • Start with deny-all and explicitly allow required traffic
  • Use meaningful label conventions (tier, app, env)
  • Label namespaces for cross-namespace policies
  • Test policies thoroughly in staging first
  • Document traffic requirements
  • Monitor denied traffic using network logging
  • Use tools like Cilium to view traffic flows

Advanced Networking

  • Cilium: eBPF-based networking and security
  • Calico: Enterprise-grade networking and policy
  • Istio/Linkerd: Service mesh for advanced control
  • Network Logging: Monitor denied connections
  • DNS Policies: Control DNS resolution
