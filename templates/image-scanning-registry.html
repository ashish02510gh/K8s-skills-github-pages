Container Image Security

Container images are the foundation of your applications. Vulnerable images can introduce security risks into your cluster. Image scanning identifies vulnerabilities before they reach production.

⚠️ Important: Scan images before deployment and continuously scan running images for new vulnerabilities.

Image Scanning Tools

Trivy

Fast, comprehensive vulnerability scanner:

# Scan local image
trivy image myimage:latest

# Scan with detailed output
trivy image --severity HIGH,CRITICAL myimage:latest

# Generate report
trivy image --format json myimage:latest > report.json

Grype

Syft-based vulnerability scanner:

grype myimage:latest
grype myimage:latest -o json > report.json

Clair

Container image vulnerability detection:

  • Analyzes image layers
  • Compares against vulnerability databases
  • REST API for integration

Harbor

Enterprise container registry with scanning:

  • Built-in Trivy scanning
  • Image signing and verification
  • Access control and RBAC
  • Replication and security policies

Registry Security

Use Private Registries

  • Never pull from public registries in production
  • Use private Docker Hub, Quay, ECR, ACR, GCR
  • Implement access control
  • Enable audit logging

Registry Authentication

apiVersion: v1
kind: Secret
metadata:
  name: registry-credentials
type: kubernetes.io/dockercfg
data:
  .dockercfg: |
    {
      "registry.example.com": {
        "username": "user",
        "password": "password"
      }
    }

Pod Registry Credentials

apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  imagePullSecrets:
  - name: registry-credentials
  containers:
  - name: app
    image: registry.example.com/myapp:latest

Image Signing

Notary - Image Signing

Sign and verify container images:

# Sign image
notary key generate delegation
notary delegation add registry.example.com/myapp targets/releases user_key.pub
notary publish registry.example.com/myapp

Cosign - Sigstore

Container image signing and verification:

# Sign image
cosign sign --key cosign.key registry.example.com/myapp:latest

# Verify signature
cosign verify --key cosign.pub registry.example.com/myapp:latest

# Keyless signing (OpenID Connect)
cosign sign --oidc-provider=https://oauth.google.com registry.example.com/myapp:latest

Admission Controllers

ImagePolicyWebhook

Restrict which images can be deployed:

apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: registry.example.com/approved/myapp:v1.0  # Must match policy

Enforcement Rules

  • Only approved registries allowed
  • Require image signatures
  • Block unsigned images
  • Require image tags (no latest)

CI/CD Integration

GitHub Actions Example

name: Scan and Push
on: [push]
jobs:
  scan-and-push:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v2
    - name: Build image
      run: docker build -t myapp:$GITHUB_SHA .
    - name: Scan with Trivy
      run: trivy image myapp:$GITHUB_SHA
    - name: Push to registry
      run: docker push registry.example.com/myapp:$GITHUB_SHA

Best Practices

  • ✓ Scan all images before pushing to registry
  • ✓ Scan running images continuously
  • ✓ Use minimal base images (Alpine, Distroless)
  • ✓ Keep base images updated
  • ✓ Use private registries only
  • ✓ Implement registry access control
  • ✓ Sign all images cryptographically
  • ✓ Enforce signature verification
  • ✓ Block deployment of unsigned images
  • ✓ Require specific image tags (no latest)
  • ✓ Integrate scanning into CI/CD
  • ✓ Regular base image updates
