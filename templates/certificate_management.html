Certificates in Kubernetes

Kubernetes uses certificates for secure communication between components. The cluster generates certificates during initialization and uses them for API server, etcd, kubelet, and other components. Understanding certificate management is crucial for cluster security and preventing outages.

💡 Key Point: Kubernetes certificates typically expire after 1 year. Plan for certificate rotation before expiration.

Certificate Types

1. API Server Certificates

Used by the Kubernetes API server:

  • apiserver.crt / apiserver.key
  • Signed by cluster CA
  • Must include all API server addresses (IPs, hostnames)

2. Kubelet Certificates

Used by kubelets on worker nodes:

  • kubelet.crt / kubelet.key
  • Each node has unique certificate
  • For client and server authentication

3. etcd Certificates

Protect cluster data store:

  • etcd-server.crt / etcd-server.key
  • etcd-peer.crt / etcd-peer.key
  • Encrypt peer communication

4. Cluster CA Certificate

Root certificate signing authority:

  • ca.crt / ca.key
  • Signs all other cluster certificates
  • Trusted by all components

5. Service Account Tokens

Certificates for pod authentication:

  • Automatically issued and renewed
  • Stored in secret volumes
  • Used for API server authentication

Checking Certificate Status

View Certificate Expiration

# Check all cluster certificates
kubeadm certs check-expiration

# Check specific certificate
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -dates

# Check certificate details
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -text

Certificate Information

  • Issuer: Signing authority (usually CA)
  • Subject: Certificate owner
  • Valid From/To: Expiration dates
  • Subject Alternative Names (SANs): Additional identifiers (IPs, DNS names)

Certificate Rotation

Automatic Renewal (kubeadm)

kubeadm automatically renews certificates on control plane nodes:

# Enable automatic certificate rotation
# This happens during kubelet restart or cluster upgrade

Manual Certificate Renewal

# Renew all certificates
kubeadm certs renew all

# Renew specific certificate
kubeadm certs renew apiserver

# Verify renewal
kubeadm certs check-expiration

Manual Generation

# Generate certificate signing request
openssl req -new -key apiserver.key -out apiserver.csr \
  -subj "/CN=kube-apiserver"

# Sign with CA
openssl x509 -req -in apiserver.csr \
  -CA ca.crt -CAkey ca.key \
  -out apiserver.crt -days 365 \
  -extfile openssl.conf

Custom Certificates

Cert-Manager for Automatic Renewal

Use cert-manager to automate certificate management:

apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: my-cert
  namespace: default
spec:
  secretName: my-cert-secret
  duration: 2160h  # 90 days
  renewBefore: 720h  # 30 days
  commonName: example.com
  dnsNames:
  - example.com
  - www.example.com
  issuerRef:
    name: letsencrypt-prod
    kind: ClusterIssuer

Let's Encrypt Integration

  • Automatic certificate provisioning
  • Free TLS certificates
  • Automatic renewal before expiration
  • Works with ingress controllers

Common Certificate Issues

Expired Certificates

  • Symptom: API server won't start, certificate verification errors
  • Solution: Use kubeadm certs renew or replace expired certificates
  • Prevention: Monitor expiration dates, set renewal reminders

Wrong SAN (Subject Alternative Name)

  • Symptom: Connection refused or hostname mismatch errors
  • Solution: Regenerate certificate with correct SANs
  • Prevention: Include all IP addresses and hostnames when generating

Certificate Not Trusted

  • Symptom: TLS handshake failure, unknown CA errors
  • Solution: Ensure proper CA chain and root certificate trust
  • Prevention: Use proper PKI infrastructure

Best Practices

  • ✓ Monitor certificate expiration dates closely
  • ✓ Automate certificate renewal with cert-manager
  • ✓ Include all necessary SANs when generating
  • ✓ Keep certificate backup procedures in place
  • ✓ Rotate certificates regularly (annually minimum)
  • ✓ Use strong key sizes (2048-bit RSA minimum, 4096-bit recommended)
  • ✓ Document certificate generation and renewal procedures
  • ✓ Test certificate updates in staging first
  • ✓ Plan certificate renewal before expiration
  • ✓ Use cert-manager for automatic renewals
