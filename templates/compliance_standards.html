Compliance Overview

Kubernetes deployments must comply with industry standards and regulations. Common requirements include CIS Benchmarks, PCI-DSS for payment processing, HIPAA for healthcare, SOC 2 for service providers, and GDPR for data protection.

💡 Key Insight: Compliance is not a one-time effort. It requires continuous monitoring, testing, and remediation.

Major Compliance Standards

CIS Kubernetes Benchmark

Industry best practices for Kubernetes security:

  • Level 1: Basic hardening (everyone should do this)
  • Level 2: Advanced hardening (security-sensitive workloads)
  • Controls: 200+ security checks
  • Tools: kube-bench for automated auditing

PCI-DSS (Payment Card Industry)

For systems processing payment cards:

  • Network segmentation
  • Access control and authentication
  • Encryption in transit and at rest
  • Regular security testing and monitoring
  • Incident response procedures

HIPAA (Healthcare)

For healthcare data:

  • Data encryption requirements
  • Access control and audit logging
  • Business associate agreements
  • Breach notification procedures
  • Regular risk assessments

SOC 2 (Service Organizations)

For service providers:

  • Security, availability, processing integrity
  • Confidentiality and privacy controls
  • Regular independent audits
  • Documentation and evidence

GDPR (Data Protection)

For processing EU resident data:

  • Data protection by design
  • User consent and privacy
  • Right to access and erasure
  • Data breach notification
  • Data processing agreements

Compliance Tools

kube-bench

Automated CIS Benchmark auditing:

kube-bench run --targets node,policies

# Check specific control
kube-bench run --targets node --checks 4.1.1

# Generate JSON report
kube-bench run --json > report.json

kubesec

Security risk analysis for Kubernetes:

kubesec scan deployment.yaml
kubesec scan --severity 7 deployment.yaml

Polaris

Best practices audit for Kubernetes:

polaris audit --audit-path ./audit.json
polaris dashboard

Kubescape

Comprehensive security auditing:

kubescape scan
kubescape scan --compliance cis
kubescape scan --severity high

Compliance Checklist

Essential Controls

  • ✓ RBAC enabled and properly configured
  • ✓ Network policies implemented
  • ✓ Pod Security Standards enforced
  • ✓ Secrets encrypted at rest
  • ✓ Audit logging enabled
  • ✓ Image scanning implemented
  • ✓ TLS for all communications
  • ✓ Resource quotas configured

Hardening Controls

  • ○ Admission webhooks configured
  • ○ Runtime security monitoring
  • ○ Network segmentation
  • ○ Multi-factor authentication
  • ○ Backup and disaster recovery
  • ○ Incident response procedures

Continuous Compliance

Regular Scanning

  • Daily compliance scans using automated tools
  • Weekly vulnerability assessments
  • Monthly penetration testing
  • Quarterly risk assessments
  • Annual independent audits

Documentation

  • Maintain detailed compliance evidence
  • Document all security controls
  • Record audit findings and remediation
  • Keep incident logs and reports
  • Store policy versions and updates

Remediation

  • Create remediation plans for findings
  • Track remediation progress
  • Re-test after remediation
  • Document completion
