Secrets Overview

Kubernetes Secrets are objects used to store and manage sensitive data like passwords, API keys, SSH keys, and OAuth tokens. By default, secrets are stored as base64-encoded text in etcd. For production, always encrypt secrets at rest.

⚠️ Important: Base64 is encoding, not encryption. Always encrypt secrets at rest using KMS or encrypted etcd.

Secret Types

1. Opaque Secrets (Default)

Arbitrary user-defined data:

apiVersion: v1
kind: Secret
metadata:
  name: db-credentials
type: Opaque
data:
  password: cGFzc3dvcmQxMjM=  # base64 encoded
  username: YWRtaW4=

2. Service Account Tokens

Automatically created for each service account:

type: kubernetes.io/service-account-token

3. TLS/SSL Certificates

Store certificates and keys:

apiVersion: v1
kind: Secret
metadata:
  name: tls-secret
type: kubernetes.io/tls
data:
  tls.crt: BASE64_ENCODED_CERT
  tls.key: BASE64_ENCODED_KEY

4. Docker Registry Credentials

Authentication for private registries:

type: kubernetes.io/dockercfg

Encryption at Rest

Enable Encryption Provider

Configure kube-apiserver with encryption configuration:

--encryption-provider-config=/etc/kubernetes/encryption-config.yaml

Encryption Policy Example

apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
- resources:
  - secrets
  providers:
  - aescbc:
      keys:
      - name: key1
        secret: rWtsy+O4008S2Z5+DcjokQ==
  - identity: {}

Using External Key Management

  • AWS KMS: Key management service
  • Azure Key Vault: Cloud key storage
  • HashiCorp Vault: Open-source secrets engine
  • Google Cloud KMS: Google's key management

Using Secrets in Pods

As Environment Variables

apiVersion: v1
kind: Pod
metadata:
  name: app-pod
spec:
  containers:
  - name: app
    image: myapp:latest
    env:
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: db-credentials
          key: password

As Volume Mounts

apiVersion: v1
kind: Pod
metadata:
  name: app-pod
spec:
  containers:
  - name: app
    image: myapp:latest
    volumeMounts:
    - name: secret-volume
      mountPath: /etc/secrets
      readOnly: true
  volumes:
  - name: secret-volume
    secret:
      secretName: db-credentials

Secret Rotation

  • Rotate secrets regularly (quarterly minimum)
  • Use external secret controllers for automation
  • Implement graceful secret updates
  • Monitor secret access and usage
  • Archive old secrets for audit purposes

Best Practices

  • ✓ Always encrypt secrets at rest using KMS
  • ✓ Use external secret stores (Vault, AWS Secrets Manager)
  • ✓ Never commit secrets to version control
  • ✓ Use sealed secrets or external-secrets operator
  • ✓ Implement RBAC for secret access
  • ✓ Audit all secret access
  • ✓ Rotate secrets regularly
  • ✓ Use service accounts over long-lived passwords
  • ✓ Store secrets in memory, not on disk
  • ✓ Use TLS for secret transmission

Tools & Solutions

  • Sealed Secrets: Encrypt secrets for GitOps
  • External Secrets Operator: Sync with external stores
  • HashiCorp Vault: Enterprise secret management
  • Akeyless: Cloud-native secret vault
  • AWS Secrets Manager: AWS native solution
