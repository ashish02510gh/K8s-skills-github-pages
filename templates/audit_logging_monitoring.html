Audit Logging Overview

Kubernetes audit logs record all API requests made to the cluster. Enabling audit logging is essential for security, compliance, and troubleshooting. Audit logs help detect unauthorized access attempts, security breaches, and policy violations.

💡 Key Benefit: Audit logs provide forensic evidence of what happened in your cluster and who did it.

Audit Log Levels

None

Don't log the request (usually for healthchecks and probes)

Metadata

Log request metadata but not request/response body:

  • User, timestamp, verb, resource
  • Minimal overhead
  • Good for detecting patterns

Request

Log metadata and request body:

  • Useful for seeing what was requested
  • More storage/performance overhead

RequestResponse

Log metadata, request body, and response:

  • Complete record of what happened
  • Highest storage/performance cost
  • Essential for sensitive resources (secrets)

Enabling Audit Logging

API Server Configuration

--audit-log-path=/var/log/kubernetes/audit.log
--audit-log-maxage=30
--audit-log-maxbackup=10
--audit-log-maxsize=100
--audit-policy-file=/etc/kubernetes/audit-policy.yaml

Audit Policy File

apiVersion: audit.k8s.io/v1
kind: Policy
# Log secrets at request/response level
- level: RequestResponse
  resources: ["secrets"]
  omitStages:
  - RequestReceived

# Log pod exec at request level
- level: Request
  verbs: ["exec"]
  resources: ["pods/exec"]

# Log namespace changes
- level: RequestResponse
  verbs: ["create", "delete", "patch"]
  resources: ["namespaces"]

# Log RBAC changes
- level: RequestResponse
  resources: ["rolebindings", "clusterrolebindings"]

# Default: log metadata
- level: Metadata
  omitStages:
  - RequestReceived

Runtime Security Monitoring

Falco - Runtime Security

Use Falco to detect suspicious runtime behavior:

  • Monitor system calls
  • Detect privilege escalation
  • Identify unauthorized file access
  • Catch container escapes

Sysdig - System Monitoring

  • Real-time container monitoring
  • Network traffic inspection
  • Resource usage tracking
  • Forensic analysis

Prometheus & Grafana

  • Collect cluster metrics
  • Monitor API server performance
  • Track resource usage
  • Create dashboards

What to Monitor

Critical Events

  • RBAC permission changes
  • Secret access and creation
  • Pod exec and port-forward
  • Privileged container creation
  • Network policy modifications
  • Node cordoning/draining

Suspicious Patterns

  • Failed authentication attempts
  • Unauthorized access attempts
  • Unusual API patterns
  • High volume requests
  • Out-of-hours access
  • Unusual resource modifications

Example: Secret Access Alert

# Alert on secret access
- alert: SecretAccess
  expr: audit_event_count{resource="secrets"} > 5
  for: 5m
  annotations:
    summary: "High number of secret accesses detected"
    description: "{{ $value }} secret accesses in 5 minutes"

Best Practices

  • ✓ Enable audit logging on all clusters
  • ✓ Set RequestResponse level for sensitive resources
  • ✓ Implement log forwarding to secure location
  • ✓ Set appropriate log retention (30+ days)
  • ✓ Protect audit logs from tampering
  • ✓ Deploy runtime monitoring (Falco)
  • ✓ Set up alerting for suspicious activities
  • ✓ Review logs regularly for anomalies
  • ✓ Archive logs for long-term retention
  • ✓ Conduct regular forensic analysis
